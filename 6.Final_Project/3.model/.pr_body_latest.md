## 작업한 내용
- ADR-069 후속: BM25 인덱스 상한(`rag_bm25_max_docs`), 문서 압축기(`rag_use_compressor`, `rag_compressor_top_k`) 설정 추가
- 재정렬 단계 `_rerank()` 명시 및 question → retriever → RRF merge → rerank → [compressor] → context 흐름 정리
- invoke 시점 가중치 오버라이드: `retrieve_context(..., dense_weight=, sparse_weight=)` 로 A/B 테스트 지원
- 앙상블 실패 시 dense-only fallback, `get_running_loop()` 사용, LLMChainExtractor 선택 적용

## 참고 사항
- 압축기는 기본 비활성(`rag_use_compressor=False`). 활성화 시 LLM 호출·지연 증가
- 코드 리뷰 권장: 앙상블 실패 로그에 예외 타입만 남기기 (`type(e).__name__`)
