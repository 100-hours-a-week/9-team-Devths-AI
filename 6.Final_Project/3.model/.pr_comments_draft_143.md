# PR #143 리뷰 코멘트 초안

## PR: fix: Gemini 503/429 시 다중 API 키 폴백 및 재시도 적용

---

### 파일: `app/services/llm_service.py`

- **L97–114**: [Good] `_is_retryable_with_next_key`, `_is_429_quota_error` 정적 메서드 추가로 503/429/키 오류 시 다음 키 재시도 조건이 명확해짐.
- **L330**: [Good] 스트리밍 경로에서 `_is_api_key_error` → `_is_retryable_with_next_key`로 확장해 503/429도 다음 키 시도.
- **L334, L477**: [참고] `str(e)[:200]` 로그는 에러 메시지 길이 제한으로 적절. 민감 정보 포함 가능성은 기존과 동일.
- **L352–361**: [Good] 모든 키 실패 시 API 키 오류와 503/429를 구분해 사용자 메시지 분리 (키 오류 vs 일시적/쿼터).
- **L444–498**: [Good] `generate_response_non_stream`에 클라이언트 순환 루프 추가로 채팅방 제목·오프닝 메시지 등도 다중 키 폴백 적용.
- **L697–698**: [Good] 429 발생 시 다음 attempt 전 5초 대기로 쿼터 재시도 간격 확보.
- **L702–758**: [Good] `_call_gemini_with_retry`에서 시도마다 `_get_shuffled_clients()` 순회, 재시도 불가 오류 시에만 `raise`하여 의도대로 동작.

---

### 전체 코멘트 (PR 본문용)

- 503/429 시 다른 API 키로 재시도하도록 폴백 조건을 확장해, 다중 키 환경에서 가용성 개선이 기대됩니다.
- 스트리밍·비스트리밍·분석 경로 모두 동일한 `_is_retryable_with_next_key` 기준으로 통일되어 유지보수에 유리합니다.
- 429 시 5초 대기 후 재시도는 쿼터 리셋 전 재호출을 줄이는 데 도움이 됩니다.
