## 발견 사항

### Critical (반드시 수정)
- 없음

### Warning (권장 수정)

1. **[rag_service.py] 로그 메시지에 예외 내용 직접 노출**
   - `logger.warning("RAG ensemble failed, fallback to dense-only: %s", e)` 에서 `e`에 스택/메시지가 포함될 수 있어, 운영 환경에서 과도한 정보가 남을 수 있음.
   - **제안**: `logger.warning("RAG ensemble failed, fallback to dense-only: %s", type(e).__name__)` 또는 메시지만 잘라서 기록.

2. **[rag_service.py] `_compress_pairs_with_llm` 반환 시 압축 실패 구간**
   - `len(compressed_docs) != len(to_compress)` 이면 전체 `pairs`를 그대로 반환함. 압축된 앞부분 + 나머지 비압축을 합쳐 반환하는 방식도 검토 가능 (선택).
   - 현재는 “실패 시 비압축 전체 반환”으로 동작하므로 기능상 문제 없음.

### Good (잘된 점)
- **단일 책임**: `_rerank`, `_compress_pairs_with_llm` 역할이 명확하고, 앙상블·재정렬·압축 단계가 분리되어 있음.
- **에러 처리**: 앙상블 블록 전체 try/except + dense-only fallback, 압축기 실패 시 비압축 반환으로 안정적 동작.
- **성능**: `rag_bm25_max_docs`로 BM25 인덱스 상한 적용, `get_running_loop()` 사용으로 비동기 컨텍스트 적절.
- **설정**: BM25 상한·압축기·상위 k가 설정으로 분리되어 운영·실험에 유리함.
- **호출 시 가중치**: `dense_weight`/`sparse_weight` 인자로 invoke 시점 A/B 테스트 가능.
- **타입 힌트**: `list[tuple[str, Document]]`, `float | None` 등 일관되게 사용됨.
- **선택적 의존성**: `LLMChainExtractor` import 실패 시 `None` 처리로 동작 유지.

1. 로그에 예외 객체 대신 `type(e).__name__` 또는 짧은 메시지만 남기기.
