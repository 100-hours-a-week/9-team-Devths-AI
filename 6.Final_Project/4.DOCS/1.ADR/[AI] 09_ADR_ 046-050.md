## ADR-046: ChromaDB 운영 모드 선정 (Embedded → Server Mode)

### 📋 메타데이터

| 항목 | 내용 |
|------|------|
| **상태** | ✅ 승인됨 (Accepted) |
| **작성일** | 2026-01-21 |
| **결정자** | AI/인프라팀 |
| **관련 기능** | VectorDB, RAG, 임베딩 저장소 |

---

### 🎯 컨텍스트 (Context)

ChromaDB는 RAG(Retrieval-Augmented Generation) 구현을 위한 벡터 데이터베이스로, **Embedded Mode**와 **Server Mode** 두 가지 운영 방식을 지원합니다.

**현재 상태:**
```python
# app/services/vectordb_service.py (현재 코드)
self.chroma_client = chromadb.Client(Settings(
    persist_directory="./chroma_db",
    anonymized_telemetry=False
))
```

**문제점:**
- 전통적인 DBMS(PostgreSQL 등)와 달리 ChromaDB는 운영 모드에 따라 인프라 설정이 크게 다름
- V1(단일 인스턴스)과 V2+(다중 인스턴스) 환경에서 요구사항이 상이함
- 인증/접근 제어 방식이 모드에 따라 다름

**요구사항:**
- V1: 단순한 설정, 빠른 개발
- V2+: 다중 FastAPI 인스턴스에서 동시 접근
- V3+: Kubernetes 환경에서 중앙 집중식 관리

---

### 🔍 선택지 분석 (Options)

#### Option 1: Embedded Mode (임베딩 모드) - V1 권장 ⭐

```python
# FastAPI 애플리케이션 내부에서 직접 실행
import chromadb
from chromadb.config import Settings

client = chromadb.PersistentClient(
    path="./chroma_db"
)

# 또는 메모리 전용 (테스트용)
client = chromadb.EphemeralClient()
```

**특징:**
- FastAPI 프로세스 내부에서 ChromaDB 라이브러리 실행
- 로컬 파일 시스템에 직접 저장 (`./chroma_db`)
- 네트워크 통신 없음
- 토큰/인증 불필요

**아키텍처:**
```
┌─────────────────────────────────────┐
│  FastAPI 서버 (단일 인스턴스)        │
│  ├─ FastAPI Application             │
│  ├─ ChromaDB Library (Embedded)     │
│  └─ 로컬 파일 시스템 (./chroma_db)  │
└─────────────────────────────────────┘
```

| 장점 | 단점 |
|------|------|
| ✅ **설정 간단** (별도 서버 불필요) | ❌ 여러 인스턴스 동시 접근 불가 |
| ✅ **네트워크 레이턴시 없음** | ❌ 수평 확장 어려움 |
| ✅ **토큰/인증 불필요** | ❌ FastAPI와 리소스 공유 |
| ✅ **빠른 처리 속도** | ❌ 독립적 스케일링 불가 |
| ✅ **비용 절감** (서버 1대) | - |

---

#### Option 2: Server Mode (서버 모드) - V2+ 권장 ⭐

```python
# FastAPI는 클라이언트, ChromaDB는 별도 서버
import chromadb
from chromadb.config import Settings

client = chromadb.HttpClient(
    host="chromadb-server.internal",
    port=8000,
    settings=Settings(
        chroma_client_auth_provider="chromadb.auth.token.TokenAuthClientProvider",
        chroma_client_auth_credentials=os.getenv("CHROMA_AUTH_TOKEN")
    )
)
```

**특징:**
- 별도의 ChromaDB 서버 프로세스 실행
- HTTP/HTTPS로 통신
- 여러 클라이언트가 동시 접근 가능
- 토큰 기반 인증 지원

**아키텍처:**
```
┌─────────────┐
│     ALB     │
└──────┬──────┘
   ┌───┴───┐
   ▼       ▼
┌────┐  ┌────┐      ┌─────────────┐
│API1│  │API2│ ───→ │ ChromaDB    │
└────┘  └────┘      │ Server      │
                    │ (별도 서버) │
                    └─────────────┘
```

| 장점 | 단점 |
|------|------|
| ✅ **여러 인스턴스 동시 접근** | ⚠️ 별도 서버 관리 필요 |
| ✅ **독립적 스케일링** | ⚠️ 네트워크 레이턴시 존재 |
| ✅ **중앙 집중식 관리** | ⚠️ 설정 복잡도 증가 |
| ✅ **리소스 분리** | ⚠️ 추가 인프라 비용 |
| ✅ **토큰 기반 보안** | - |

### ✅ 결정 (Decision)

**버전별 ChromaDB 운영 모드 전략**

| 버전 | 운영 모드 | 이유 |
|------|----------|------|
| **V1 (MVP)** | **Embedded Mode** | 단일 인스턴스, 설정 간단 |
| **V2 (Production)** | **Server Mode** | 다중 인스턴스 (ALB), 중앙 관리 |
| **V3 (Enterprise)** | **Server Mode (K8s)** | Kubernetes 환경, 서비스 분리 |

---

### 📝 근거 (Rationale)

#### 1. 전통적인 DBMS와의 차이점

| 구분 | 전통적인 DBMS (PostgreSQL) | ChromaDB Embedded Mode | ChromaDB Server Mode |
|------|---------------------------|----------------------|---------------------|
| **설치** | 별도 서버 프로세스 필요 | Python 라이브러리 포함 | 별도 서버 프로세스 필요 |
| **인증** | 사용자/비밀번호 필수 | 불필요 | 토큰 기반 인증 |
| **네트워크** | TCP/IP 연결 필요 | 파일 시스템 접근만 | HTTP/HTTPS 통신 |
| **DB 생성** | `CREATE DATABASE` 필요 | 자동 생성 (디렉토리) | 자동 생성 (API 호출) |
| **접근 권한** | `GRANT`/`REVOKE` | 파일 시스템 권한 | 토큰으로 전체 접근 |
| **컬렉션 생성** | `CREATE TABLE` 필요 | 코드에서 자동 생성 | 코드에서 자동 생성 |

**핵심 차이:**
- ✅ ChromaDB는 **스키마 사전 정의 불필요**
- ✅ 컬렉션(Collection)은 **코드에서 자동 생성**
- ✅ Embedded Mode는 **인증 설정 불필요**
- ✅ Server Mode는 **토큰 하나로 전체 접근**

---

#### 2. V1 (MVP) - Embedded Mode 선택 근거

**현재 코드 분석:**
```python
# app/services/vectordb_service.py
self.chroma_client = chromadb.Client(Settings(
    persist_directory="./chroma_db",
    anonymized_telemetry=False
))
```

**V1 환경:**
- EC2 1대 (단일 FastAPI 인스턴스)
- 트래픽: 낮음 (MVP 단계)
- 동시 접근: 없음

**Embedded Mode 장점:**
```
✅ 설정 간단
   - 별도 ChromaDB 서버 불필요
   - 환경변수 설정 최소화
   - 인증 토큰 불필요

✅ 빠른 개발
   - 로컬 파일 시스템 접근만
   - 네트워크 설정 불필요
   - 즉시 사용 가능

✅ 비용 절감
   - 서버 1대만 필요
   - 추가 인프라 비용 없음

✅ 성능
   - 네트워크 레이턴시 없음
   - 로컬 I/O만 사용
```

**인프라 설정 (V1):**
```yaml
필수 설정:
  - 파일 시스템 권한: ./chroma_db 쓰기 권한
  - 디스크 용량: 임베딩 벡터 저장 공간

선택 설정:
  - 백업: ./chroma_db 디렉토리 정기 백업
  - 모니터링: 디스크 사용량 모니터링

불필요:
  ❌ 별도 ChromaDB 서버
  ❌ 토큰/인증 설정
  ❌ 네트워크 방화벽 설정
```

#### 3. V2 (Production) - Server Mode 전환 근거

**V2 환경:**
- ALB + 다중 FastAPI 인스턴스 (2대 이상)
- 트래픽: 증가 (Production 단계)
- 동시 접근: 여러 인스턴스에서 동일한 VectorDB 접근 필요

**Server Mode 필요성:**
```
⚠️ Embedded Mode 문제점:
   - 각 FastAPI 인스턴스가 독립적인 ./chroma_db 보유
   - 데이터 불일치 발생 (인스턴스 A에 저장 → 인스턴스 B에서 조회 불가)
   - 파일 시스템 동기화 복잡

✅ Server Mode 해결:
   - 중앙 집중식 ChromaDB 서버
   - 모든 FastAPI 인스턴스가 동일한 데이터 접근
   - 데이터 일관성 보장
```

**마이그레이션 전략:**

```python
# V1 → V2 전환 코드 (환경변수로 모드 전환)
import os
import chromadb
from chromadb.config import Settings

CHROMA_MODE = os.getenv("CHROMA_MODE", "embedded")  # "embedded" or "server"

if CHROMA_MODE == "server":
    # V2: Server Mode
    client = chromadb.HttpClient(
        host=os.getenv("CHROMA_HOST", "chromadb-server.internal"),
        port=int(os.getenv("CHROMA_PORT", 8000)),
        settings=Settings(
            chroma_client_auth_provider="chromadb.auth.token.TokenAuthClientProvider",
            chroma_client_auth_credentials=os.getenv("CHROMA_AUTH_TOKEN")
        )
    )
else:
    # V1: Embedded Mode (호환성 유지)
    client = chromadb.PersistentClient(path="./chroma_db")

collection = client.get_or_create_collection("resumes")
```

**ChromaDB 서버 실행 (Docker):**
```bash
# Docker로 ChromaDB 서버 실행 (권장)
docker run -d \
  --name chromadb-server \
  -p 8000:8000 \
  -v /data/chroma:/chroma/chroma \
  -e CHROMA_SERVER_AUTH_CREDENTIALS="your-secret-token" \
  --restart unless-stopped \
  chromadb/chroma:latest

# 또는 docker-compose.yml 사용
version: '3.8'
services:
  chromadb:
    image: chromadb/chroma:latest
    ports:
      - "8000:8000"
    volumes:
      - ./chroma_data:/chroma/chroma
    environment:
      - CHROMA_SERVER_AUTH_CREDENTIALS=${CHROMA_AUTH_TOKEN}
    restart: unless-stopped
```

**Docker 사용의 장점:**
- ✅ 공식 이미지 제공 (안정성)
- ✅ 버전 관리 용이
- ✅ 배포/롤백 간편
- ✅ 리소스 격리
- ✅ 전통적인 DBMS와 동일한 운영 방식

**인프라 설정 (V2):**
```yaml
필수 설정:
  - ChromaDB 서버 1대 (Docker 또는 별도 EC2)
  - 토큰 생성 및 환경변수 설정
  - 네트워크 방화벽: FastAPI → ChromaDB 포트 허용
  - 데이터 영속성: 볼륨 마운트 (/data/chroma)

선택 설정:
  - 백업: ChromaDB 데이터 디렉토리 백업
  - 모니터링: ChromaDB 서버 상태 모니터링
  - 로깅: ChromaDB 로그 수집
```

#### 4. V3 (Enterprise) - Kubernetes Server Mode

**V3 환경:**
- Kubernetes (EKS)
- 여러 AI Pod에서 동시 접근
- 엔터프라이즈급 안정성 요구

**Kubernetes 배포:**
```yaml
# chromadb-deployment.yaml
apiVersion: v1
kind: Service
metadata:
  name: chromadb
  namespace: ai-services
spec:
  selector:
    app: chromadb
  ports:
    - port: 8000
      targetPort: 8000
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: chromadb
  namespace: ai-services
spec:
  replicas: 1
  selector:
    matchLabels:
      app: chromadb
  template:
    metadata:
      labels:
        app: chromadb
    spec:
      containers:
      - name: chromadb
        image: chromadb/chroma:latest
        ports:
        - containerPort: 8000
        env:
        - name: CHROMA_SERVER_AUTH_CREDENTIALS
          valueFrom:
            secretKeyRef:
              name: chroma-secret
              key: auth-token
        volumeMounts:
        - name: chroma-data
          mountPath: /chroma/chroma
      volumes:
      - name: chroma-data
        persistentVolumeClaim:
          claimName: chroma-pvc
---
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: chroma-pvc
  namespace: ai-services
spec:
  accessModes:
    - ReadWriteOnce
  resources:
    requests:
      storage: 50Gi
```

**FastAPI Pod 연결:**
```python
# Kubernetes 환경에서 서비스 디스커버리
client = chromadb.HttpClient(
    host="chromadb.ai-services.svc.cluster.local",  # K8s 서비스 DNS
    port=8000,
    settings=Settings(
        chroma_client_auth_provider="chromadb.auth.token.TokenAuthClientProvider",
        chroma_client_auth_credentials=os.getenv("CHROMA_AUTH_TOKEN")
    )
)
```

#### 3. 인프라 팀을 위한 상세 가이드

**Q: ChromaDB를 Docker로 올리는 것이 좋은가요?**

**A: 네, Docker 사용을 권장합니다.** 하지만 전통적인 DBMS와는 다릅니다:

| 구분 | 전통적인 DBMS (PostgreSQL) | ChromaDB (Server Mode) |
|------|---------------------------|------------------------|
| **Docker 사용** | ✅ 권장 (공식 이미지 제공) | ✅ 권장 (공식 이미지 제공) |
| **데이터 영속성** | 볼륨 마운트 필수 | 볼륨 마운트 필수 |
| **인증 설정** | 사용자/비밀번호 | 토큰 기반 (단순) |
| **DB 생성** | `CREATE DATABASE` 필요 | ❌ 불필요 (자동 생성) |
| **스키마 정의** | DDL 필요 | ❌ 불필요 (코드에서 자동) |

**Docker 사용 예시:**
```bash
# ChromaDB 서버 실행 (Docker)
docker run -d \
  --name chromadb-server \
  -p 8000:8000 \
  -v /data/chroma:/chroma/chroma \
  -e CHROMA_SERVER_AUTH_CREDENTIALS="your-secret-token" \
  chromadb/chroma:latest
```

**인프라 팀이 설정해야 할 항목:**

```yaml
필수 설정:
  1. ChromaDB 서버 실행
     - Docker 컨테이너 또는 별도 EC2
     - 포트: 8000 (기본값)
     - 데이터 영속성: 볼륨 마운트 (/data/chroma)
  
  2. 인증 토큰
     - 환경변수: CHROMA_SERVER_AUTH_CREDENTIALS
     - FastAPI와 동일한 토큰 공유
     - 보안: 환경변수 또는 Secret Manager 사용
  
  3. 네트워크 접근
     - FastAPI → ChromaDB 포트 허용 (8000)
     - 방화벽 규칙 설정
     - 내부 네트워크 권장 (공개 IP 불필요)

선택 설정:
  4. 백업 정책
     - /data/chroma 디렉토리 정기 백업
     - 스냅샷 또는 파일 시스템 백업
  
  5. 모니터링
     - ChromaDB 서버 상태 모니터링
     - 메모리/디스크 사용량 추적
     - 로그 수집
  
  6. 리소스 제한
     - 메모리 제한 (예: 4GB)
     - CPU 제한 (예: 2 cores)
     - 디스크 할당량
```

**인프라 팀이 설정할 필요 없는 항목:**

```yaml
❌ DB 생성: 코드에서 자동 생성
❌ 테이블/컬렉션 생성: 코드에서 자동 생성
❌ 스키마 정의: 불필요
❌ 사용자 권한 관리: 토큰 하나로 전체 접근

```

#### 4. 임베딩 생성에 대한 명확한 설명

**Q: 서버 모드로 바꾸면 임베딩을 못 만드나요?**

**A: 아니요! 서버 모드에서도 임베딩은 그대로 생성 가능합니다.**

**임베딩 생성 프로세스 (모드와 무관):**

```
1. FastAPI 애플리케이션
   └─> Gemini Embedding API 호출
       └─> gemini-embedding-001 모델 사용
           └─> 벡터 생성 (768차원)

2. 생성된 벡터를 ChromaDB에 저장
   ├─ Embedded Mode: 로컬 파일 시스템에 저장
   └─ Server Mode: HTTP로 ChromaDB 서버에 전송
```

**코드 예시:**
```python
# app/services/vectordb_service.py
# 임베딩 생성은 모드와 무관하게 동일
async def create_embedding(self, text: str) -> List[float]:
    # Gemini API로 임베딩 생성 (FastAPI에서 실행)
    result = self.genai_client.models.embed_content(
        model="gemini-embedding-001",
        contents=text
    )
    return result.embeddings[0].values

# 생성된 벡터를 ChromaDB에 저장
# Embedded Mode: 로컬 파일에 저장
# Server Mode: HTTP로 서버에 전송
await self.vectordb.add_document(
    document_id=doc_id,
    text=text,
    collection_type="resume"
)
```

**핵심 정리:**
- ✅ **임베딩 생성**: FastAPI에서 Gemini API 호출 (모드와 무관)
- ✅ **벡터 저장**: ChromaDB에 저장 (모드에 따라 저장 방식만 다름)
- ✅ **Embedded Mode**: 로컬 파일 시스템에 직접 저장
- ✅ **Server Mode**: HTTP로 ChromaDB 서버에 전송하여 저장
